## ⚠️ 关键一致性要求

### 虚拟按钮实现（必须一致）

**规范文档**: `GAME_DEVELOPMENT_GUIDE.md`
**实际代码**: `/games/*.html`

**检查点**:
1. 所有游戏页面必须使用相同的虚拟按钮实现模板
2. 必须创建完整的 KeyboardEvent 对象
3. 必须调用 `e.preventDefault()`

**验证方法**:
```bash
# 检查所有游戏是否使用正确的实现
grep -r "new KeyboardEvent" games/*.html
```

### 测试覆盖（必须一致）

**规范文档**: `PREVENTING_GAME_BUGS.md`
**测试文件**: `/e2e/*-auto.spec.ts`

**检查点**:
1. 每个游戏都有对应的自动化测试
2. 测试必须包含物理键盘和虚拟按钮
3. 测试脚本必须在 `package.json` 中注册

**验证方法**:
```bash
# 检查测试覆盖
npm run test:games
```

## 🤖 自动化一致性检查

### 创建检查脚本
```bash
# 运行一致性检查
npm run verify:docs-consistency
```

### 检查内容
1. **代码与规范一致性**
   - 所有游戏是否使用正确的虚拟按钮实现
   - 所有游戏是否暴露 gameInstance 到 window

2. **测试覆盖一致性**
   - 每个游戏是否有对应的测试文件
   - package.json 是否包含所有测试命令

3. **文档引用一致性**
   - 文档中提到的文件是否存在
   - 文档中的代码示例是否与实际代码一致

## 📝 文档更新原则

### 单一真相源（Single Source of Truth）

**规范定义**: `GAME_DEVELOPMENT_GUIDE.md`
- 这是虚拟按钮实现的唯一权威文档
- 所有其他文档只能引用它，不能重复定义

**使用说明**: `PREVENTING_GAME_BUGS.md`
- 这是工作流程的唯一权威文档
- 只说明如何使用，不重复技术细节

### 引用而不是复制

❌ **错误做法**:
```markdown
<!-- 在多个文档中复制相同的代码示例 -->
```

✅ **正确做法**:
```markdown
<!-- 引用规范文档 -->
详细实现请参考 [游戏开发规范指南](./GAME_DEVELOPMENT_GUIDE.md#虚拟按钮实现)
```

### 更新流程

```
修改规范 → 更新代码 → 更新测试 → 运行验证 → 更新引用文档
```
