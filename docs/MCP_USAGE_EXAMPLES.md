# MCP 使用示例 (MCP Usage Examples)

本文档展示如何在 GitHub Copilot 中使用博物馆搜索 MCP 工具。

## 前提条件

1. 已安装依赖：`npm install`
2. GitHub Copilot 已启用并配置（读取 `.copilot-mcp.json`）
3. MCP 服务器已启动（自动或手动：`npm run mcp:start`）

## 使用场景和示例

### 场景 1: 验证博物馆数据准确性

**在 Copilot 聊天中询问：**

```
请搜索"故宫博物院"的官方数据，我想验证我们应用中的信息是否准确
```

**Copilot 将调用 `search_official_museums` 工具，返回：**

```json
{
  "searchTerm": "故宫",
  "totalResults": 4,
  "museums": [
    {
      "名称": "故宫博物院",
      "省份": "北京市",
      "质量等级": "一级",
      "藏品数量": "1950828",
      "年度参观人数_万人": "1762.4483"
    }
    // ... 更多结果
  ]
}
```

### 场景 2: 查找特定地区的博物馆

**询问：**

```
搜索"上海"相关的博物馆，我想了解上海地区有哪些主要博物馆
```

**结果：** 返回所有包含"上海"关键词的官方博物馆列表

### 场景 3: 编写博物馆介绍时获取真实数据

**询问：**

```
我正在为"中国国家博物馆"编写介绍，请提供官方的藏品数量和参观人数数据
```

**Copilot 将：**
1. 调用 museum search API
2. 提取相关统计数据
3. 帮助你生成准确的介绍文字

### 场景 4: 批量验证博物馆等级

**询问：**

```
搜索"故宫"，告诉我结果中有多少个一级博物馆
```

**Copilot 将：**
1. 搜索所有包含"故宫"的博物馆
2. 分析质量等级字段
3. 统计一级博物馆数量

### 场景 5: 对比不同博物馆的规模

**询问：**

```
分别搜索"故宫博物院"和"上海博物馆"，比较它们的藏品数量
```

**Copilot 将：**
1. 分别搜索两个博物馆
2. 提取藏品数量
3. 进行对比分析

## API 返回的字段说明

每个博物馆包含以下信息：

| 字段 | 说明 | 示例 |
|-----|------|------|
| 名称 | 博物馆官方名称 | 故宫博物院 |
| 省份 | 所在省市 | 北京市 |
| 性质 | 博物馆性质 | 文化文物系统国有博物馆 |
| 质量等级 | 一级/二级/三级/未定级 | 一级 |
| 免费开放 | 是否免费 | 是/否 |
| 藏品数量 | 馆藏文物数量 | 1950828 |
| 珍贵文物数量 | 珍贵文物数量 | 1053272 |
| 年度展览次数 | 年度举办展览数 | 78 |
| 年度教育活动次数 | 年度教育活动数 | 1634 |
| 年度参观人数_万人 | 年度参观人数（万） | 1762.4483 |

## 故障排除

### Copilot 无法调用 MCP 工具

1. 检查 `.copilot-mcp.json` 文件是否在项目根目录
2. 重启 VS Code 或 GitHub Copilot 扩展
3. 确认 MCP 服务器可以手动启动：`npm run mcp:start`

### 搜索结果为空

- 尝试使用更简短的关键词（如"故宫"而不是"故宫博物院"）
- 检查拼写是否正确
- 某些小型博物馆可能未收录在官方数据库中

### API 请求失败

- 检查网络连接
- 确认 API 端点可访问：`curl https://letmetry.cloud/museum/search`
- 查看 MCP 服务器日志输出

## 最佳实践

1. **使用准确的关键词**：尽量使用博物馆的核心名称
2. **验证结果**：搜索到多个结果时，确认选择正确的博物馆
3. **缓存数据**：如果需要频繁使用，考虑缓存官方数据
4. **定期更新**：官方统计数据每年更新，定期验证应用中的数据
