## 📋 功能详解

### 核心逻辑流程

```
用户打开应用
    ↓
检查 visitedMuseumsMeta 是否有记录
    ↓
├─ 有记录 → 返回用户路径
│   ├─ 加载已访问博物馆列表
│   ├─ 按时间戳降序排序（最新的在前）
│   └─ 仅渲染这些博物馆的卡片
│
└─ 无记录 → 新用户路径
    ├─ 尝试获取用户城市
    ├─ 显示该城市的博物馆（有定位时按距离排序）
    └─ 或显示热门博物馆列表
```

### 数据存储

**visitedMuseumsMeta** 格式：
```json
{
    "forbidden-city": 1705282400000,
    "national-museum": 1705195000000,
    "shanghai-museum": 1705107600000
}
```

- 时间戳越大 = 越近的访问
- 排序时使用 `b[1] - a[1]` 确保降序

### 用户交互流程

1. **首次访问**：看到所有/推荐博物馆
2. **点击博物馆卡片**：进入详情页
3. **标记"已打卡"**：
   - 更新 `visitedMuseumsMeta[museumId] = Date.now()`
   - 保存到 localStorage
4. **返回主页**（刷新或重新访问）：
   - 读取 `visitedMuseumsMeta`
   - 按时间戳排序
   - 只显示已访问的博物馆

## 📞 故障排除

### 问题：用户仍看到所有博物馆
**检查**：
1. DevTools > Application > Local Storage > visitedMuseumsMeta 是否为空
2. 用户是否真的打卡过博物馆
3. 浏览器是否在隐私模式（localStorage 可能被禁用）

### 问题：排序不正确
**检查**：
1. 验证时间戳值是否正确（应为毫秒整数）
2. 确认排序函数 `b[1] - a[1]` 未被修改
3. 检查浏览器控制台是否有 JavaScript 错误

### 问题：打卡后排序未更新
**检查**：
1. 确认点击"已打卡"后页面是否刷新
2. localStorage 中的时间戳是否更新
3. 浏览器是否清除了 localStorage
