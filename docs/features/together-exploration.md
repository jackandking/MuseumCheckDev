# 同行探索活动入口

## Why

MuseumCheck 的主要使用时刻在真实参观中。`together.html` 是一个小型、可逆的活动入口实验：先由发起者确定馆、日期和集合时间，再把报名链接发给有计划到馆的家庭，而不是把泛兴趣浏览当作一次现场参观。

## Flow

1. `together.html` 首页是一个小型活动广场：维护者明确列出的场次会显示为“正在招募”；活动开始后的五小时内，首页只显示匿名的活动状态与参与家庭总数。
2. 发起者仍可在首页展开“发起一场专属同行探索”，选择一座已收录博物馆、日期、时间和 3–6 组家庭的上限。该链接不会自动进入公共活动列表。
3. 家庭填写一个临时家庭称号。默认会在该活动详情页展示给查看本场的家庭，以帮助判断是否已有同行者；家庭可以关闭展示。服务端只收到匿名、不可反推个人的活动加入 ID、参与偏好，以及选择展示时的短称号；不收集姓名、联系方式或孩子信息。
4. 家庭各自进入既有的打卡任务；链接带上 `together` 活动 ID，便于匿名分析现场活动漏斗。
5. 完成任务且已经上传照片的家庭，可以明确选择：仅分享给本场同行家庭（14 天），或允许 MuseumCheck 在审核通过后作为对应任务/展品的长期“家庭发现”展示。两项均默认关闭、彼此独立。

## Safety and privacy

- 不收集姓名、电话、孩子照片、实时位置或联系人。活动页可显示报名者主动留下的临时家庭称号；该称号不应用于身份识别。
- 不提供陌生家庭私聊、自动匹配、公开成员列表、打卡照片墙、点赞或精准集合位置。活动广场仅显示维护者已发布的活动元数据和聚合人数。
- 本场发现只对已加入本场的家庭显示，不含昵称、联系方式、孩子资料或精确位置。长期公开页只读 `approved` 状态的家庭照片；待审核与被拒绝照片绝不显示。
- 参与者自己购票、自己安排节奏；共同目标是可选的，不参加也能完成参观体验。

## Validation

这不是实际活动承诺。首轮只验证：活动链接是否被实际到馆家庭打开、是否提升 `checkin_open -> task_open -> first_task_complete`，以及家庭是否觉得“轻并肩”比单独体验更有动力。
